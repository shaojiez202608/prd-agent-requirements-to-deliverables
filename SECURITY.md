# Security

## Reporting a vulnerability

If you discover a potential security issue in this project, notify AWS Security via the
[vulnerability reporting page](https://aws.amazon.com/security/vulnerability-reporting/) or by email to
aws-security@amazon.com. **Please do not create a public GitHub issue.**

## Scope

This is a prototype for non-production use (see the disclaimer in [README.md](README.md)). The sections below
describe what it deploys, how it handles data, which controls exist and where they are implemented, what to watch
out for, how to harden it, and how to remove it. More detail: [SECURITY-NOTES.md](SECURITY-NOTES.md) and
[THREAT_MODEL.md](THREAT_MODEL.md).

## What is deployed

Only with the optional `make deploy` (one CloudFormation stack, [infra/prd_infra/artifact_stack.py](infra/prd_infra/artifact_stack.py)):

| Resource | Purpose |
|---|---|
| S3 artifact bucket + bucket policy | Stores published deliverable bundles |
| S3 access log bucket + bucket policy | Receives server access logs of the artifact bucket |

No compute, no public endpoint, no IAM role, IAM user, access key or KMS key. The local tools (forms, compiler,
generator, checkers) run on your machine and deploy nothing.

## How data is handled

- Intake data is typed into an offline HTML form or a JSON file. The forms make no network request and store
  nothing; export is an explicit file download.
- The prompt is copied into an AI tool **by a person**; this project never sends data to an AI service.
- Deliverables stay on disk until a person runs `prd-agent publish`; then they are stored in the artifact bucket,
  encrypted at rest (SSE-S3) and only reachable over TLS 1.2+.
- Sample data in the repository is synthetic.

## Controls and where they are implemented

| Control | Implementation |
|---|---|
| Block Public Access, ACLs disabled, SSE-S3, TLS-only (min. 1.2), versioning, access logging, lifecycle expiry | `infra/prd_infra/artifact_stack.py` (bucket properties) |
| Bucket policy denies every principal outside the account, including anonymous requests | `infra/prd_infra/artifact_stack.py`, statement `DenyPrincipalsOutsideAccount` |
| Optional: only named principals may write objects | `infra/prd_infra/artifact_stack.py`, statement `DenyWritesExceptPublishers` (context `writer_principal_arns`) |
| Log delivery limited to the source bucket and account (`aws:SourceArn`, `aws:SourceAccount`) | Generated by CDK with the feature flag in `infra/prd_infra/config.py` |
| Config validation fails synth (names, region, cross-field rules, no account IDs in files) | `infra/prd_infra/config.py` |
| cdk-nag AwsSolutions with zero findings and no suppressions | `infra/app.py`, `tests/test_infra.py` |
| Bundles immutable (conditional writes), publish only after validation, checksums verified on fetch | `src/prd_agent/publish.py` |
| Prompt-injection hardening (data block, marker neutralisation, header echoes only known values) | `src/prd_agent/prompt.py`, `intake/compiler.js` |
| Reserved markers and non-Latin-1 text rejected before generation | `src/prd_agent/intake.py`, `intake/compiler.js` |
| Forms cannot make network requests (CSP `default-src 'none'`) | `intake/form.template.html` |
| Preflight, destructive-change guard, verification of deny paths, confirmed cleanup, residue check | `scripts/ops.py`, `Makefile` |
| Secret scanning of the full history with a canary | `scripts/scan.sh`, `.gitleaks.toml`, `.github/workflows/ci.yml` |

## Known caveats

- AI-produced deliverables can be wrong even when they are consistent; the checker covers ID, identifier and access.
- Intake text reaches an LLM through the copied prompt. Injection can only be mitigated, not prevented.
- The publish gate runs on the client. A principal with `s3:PutObject` in the account can bypass it (use
  `writer_principal_arns` and IAM to limit writers).
- Bucket names are generated in the shared global namespace; after deletion another account could create the same
  name. Do not hard-code bucket names in clients.

## Hardening before production

1. Review the knowledge-base rules, the pending-item rules and the threat model with the real teams; get the
   threat model approved (it is a draft).
2. Restrict bucket access to named publisher and reader roles (`writer_principal_arns`, IAM policies scoped to the
   bucket prefix) and remove broad account access.
3. Consider SSE-KMS with a customer managed key for the artifact bucket (the log bucket must stay on SSE-S3),
   Object Lock for released bundles, and CloudTrail data events for the bucket.
4. Use `removal_policy: retain` and set retention for noncurrent versions and access logs according to policy.
5. Put `make lint test synth scan` and `prd-agent validate`/`check-progress` into required CI checks.
6. Add a human review and an approval record before any external document (quick-start guide) is published.
7. Bundle and review a Unicode font if deliverables must contain non-Latin text.

## Cleanup

`make destroy`, then `make verify-cleanup` (see [README.md](README.md#cleanup) and [docs/cleanup.md](docs/cleanup.md)).
