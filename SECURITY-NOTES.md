# Security notes

## Least privilege
- The local tools need no credentials. Only `publish`/`fetch` against S3 and the optional CDK deployment use AWS
  credentials. These come from the caller's environment (short-lived role credentials recommended). No IAM user and
  no access key is created.
- The stack creates no IAM role or policy. The S3 bucket policies generated by CDK only deny: requests without TLS,
  requests with TLS below 1.2, and (for log delivery) they allow the S3 logging service principal to write to the
  log bucket, limited to the source bucket and account. A publisher policy example scoped to one bucket prefix is in
  docs/deployment-guide.md.
- `scripts/empty_stack_buckets.py` only touches buckets that are physical resources of the named stack, and it
  refuses stack names without the `proto-prd-` prefix. It lists only, unless `--yes` is given.

## Data protection
- S3: Block Public Access on, SSE-S3, TLS-only bucket policy (minimum TLS 1.2), versioning on the artifact bucket,
  ACLs disabled, server access logging to a separate bucket, lifecycle expiry for old versions and logs.
- The intake forms make no network request (CSP `default-src 'none'`) and store nothing. Export is an explicit file
  download.
- Sample data is synthetic.

## cdk-nag (AwsSolutions) suppressions

| Rule | Resource | Reason |
|---|---|---|
| AwsSolutions-S1 | AccessLogBucket | It is the server access log destination. Logging it into itself would loop, and adding a second log bucket only moves the finding. |

No other suppressions. `tests/test_infra.py` fails if any unsuppressed AwsSolutions error or warning appears.

## Graviton
No compute resources are deployed, so the arm64 preference does not apply.

## Known risks
- Deliverables produced by an AI agent can be wrong even when they are consistent. The checker covers ID,
  identifier and access only.
- Intake text reaches an LLM through the copied prompt. See THREAT_MODEL.md.
- The publish gate runs on the client and does not stop someone with direct S3 write access. Restrict write access
  to the publisher role.
- Bucket names are generated by CloudFormation in the shared global namespace. After deletion another account could
  create a bucket with the same name. Do not hard-code bucket names in clients.
