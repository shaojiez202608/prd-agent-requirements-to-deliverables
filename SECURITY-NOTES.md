# Security notes

Summary for users: [SECURITY.md](SECURITY.md). This file records the details behind it.

## Least privilege
- The local tools need no credentials. Only `publish`/`fetch` against S3, `make deploy/verify/destroy/verify-cleanup`
  and `make preflight` use AWS credentials from the caller's environment (short-lived role credentials recommended).
  No IAM user and no access key is created.
- The stack creates no IAM role or policy. A publisher policy example scoped to one bucket prefix is in
  docs/deployment-guide.md.
- `scripts/ops.py cleanup` only touches buckets that are physical resources of the named stack, refuses stack names
  without the `--prefix` value (default `proto-prd-`), asks for the stack name and separately before deleting data,
  and deletes from the CDK bootstrap bucket only object keys listed in this project's `cdk.out/*.assets.json`.
- `make preflight` is read-only; it shows only the last four digits of the account.

## Resource policies
Artifact bucket policy (all statements are `Deny`, so the policy cannot grant access by itself):

| Statement | Effect |
|---|---|
| CDK `enforce_ssl` | Denies requests without TLS |
| CDK `minimum_tls_version=1.2` | Denies TLS below 1.2 |
| `DenyPrincipalsOutsideAccount` | Denies `s3:*` when `aws:PrincipalAccount` is not this account. `aws:PrincipalAccount` is present in every request; for anonymous requests its value is `anonymous`, so anonymous requests are denied too ([IAM global condition keys](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_condition-keys.html)) |
| `DenyWritesExceptPublishers` (only if `writer_principal_arns` is set) | Denies `s3:PutObject` when `aws:PrincipalArn` is not one of the listed role/user ARNs. For assumed roles the key holds the role ARN, not the session ARN (same page). The ARNs come from `--context`, so no account ID is stored in the repository; the statement appears and disappears with the context value |

Access log bucket policy: TLS-only and TLS 1.2 denies, plus the `Allow` for the S3 logging service principal
`logging.s3.amazonaws.com` limited with `aws:SourceArn` (ArnLike, the artifact bucket) **and** `aws:SourceAccount`,
as the S3 documentation recommends ([enabling server access logging](https://docs.aws.amazon.com/AmazonS3/latest/userguide/enable-server-access-logging.html)).
The account-boundary deny is not added to the log bucket, because log delivery is performed by the logging service
principal and a principal-account deny must not block it (the same page warns that Deny statements must not prevent
log delivery).

## Service role trust policies
Not applicable: the stack creates no IAM role, so there is no trust policy to restrict with `aws:SourceAccount`
and `aws:SourceArn`. The only service principal in the stack (S3 log delivery, above) is already limited with both
keys. If a role is added later (for example a Lambda function), its trust policy must carry both keys.

## Data protection
- S3: Block Public Access on, SSE-S3, TLS-only bucket policy (minimum TLS 1.2), versioning on the artifact bucket,
  ACLs disabled, server access logging to a separate bucket, lifecycle expiry for old versions and logs.
- The intake forms make no network request (CSP `default-src 'none'`) and store nothing.
- Sample data is synthetic.

## Account-level settings
None are changed. The stack does not modify account-level Block Public Access, IAM settings or the `CDKToolkit`
bootstrap stack.

## cdk-nag (AwsSolutions) suppressions

None. With cdk-nag 2.38.2 the stack produces no AwsSolutions errors or warnings, with and without
`writer_principal_arns`. This is checked in `tests/test_infra.py` and by `make synth`. A harness test proves that a
bare bucket in the same harness produces AwsSolutions-S1. Any future suppression must be attached to the specific
resource path (not the whole stack), be listed in this table with a written reason, and follow configuration
changes automatically.

## gitleaks exemptions

None (`.gitleaks.toml` extends the default rules only). The canary in `scripts/scan.sh` is generated at run time
outside the repository, so it needs no exemption.

## Graviton
No compute resources are deployed, so the arm64 preference does not apply.

## Known risks
- Deliverables produced by an AI agent can be wrong even when they are consistent. The checker covers ID,
  identifier and access only.
- Intake text reaches an LLM through the copied prompt. See THREAT_MODEL.md.
- The publish gate runs on the client and does not stop someone with direct S3 write access in the account.
  `publish` uses conditional writes, so it never overwrites an existing bundle, but a plain `PutObject` from another
  tool still can (versioning keeps the old version). Use `writer_principal_arns`; consider Object Lock for released
  bundles.
- Bucket names are generated by CloudFormation in the shared global namespace. After deletion another account could
  create a bucket with the same name. Do not hard-code bucket names in clients.
